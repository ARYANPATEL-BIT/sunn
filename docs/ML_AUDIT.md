# Machine Learning Model, Dataset, Training Pipeline & Inference Audit

## 1. Executive Summary & Core Architectural Principle

Sunn is an accessibility-focused assistive communication platform for individuals with dysarthria and speech motor impairments.

### The Error-Fingerprint Principle
Instead of attempting to train a heavy, custom speech recognition foundation model on scarce dysarthric training data, Sunn adopts an innovative, lightweight paradigm:
- Commercial Hindi speech recognition (Gnani Prisma STT) consistently mishears dysarthric speech in reproducible, speaker-specific ways (for example, a slurred "पानी चाहिए" is consistently transcribed as "बानी चाइए").
- Sunn treats these consistent transcription mishearings as **acoustic error fingerprints**.
- By enrolling 2 to 3 takes of everyday phrases, Sunn turns speech recognition into a deterministic, high-speed phonetic nearest-neighbor matching task.
- When ambiguous matches arise, Groq Cloud AI reasoning (`openai/gpt-oss-120b`) is consulted as an intelligent judge.

This architecture requires zero GPU during production inference, delivers sub-5ms local matching latency, operates with total data isolation per user, and eliminates the need for massive atypical speech training datasets.

## 3. Pretrained vs Custom Model Classification

### External Pretrained Foundation Models
1. **Gnani Prisma v2.5 (`stt/v3`)**:
   - Provider: Gnani.ai
   - Role: Cloud speech-to-text transcription for Hindi (`hi-IN`) and Indian English (`en-IN`).
   - Hosting: External HTTPS API (`https://api.vachana.ai/stt/v3`).
2. **Gnani Timbre v2.5**:
   - Provider: Gnani.ai
   - Role: High-quality Hindi (`Nalini`) and English (`Kaveri`) text-to-speech synthesis.
   - Hosting: External HTTPS API (`https://api.vachana.ai/api/v1/tts/inference`).
3. **Groq Cloud `openai/gpt-oss-120b`**:
   - Provider: Groq Cloud (LPU inference engine)
   - Role: Conversational reasoning, phonetic candidate disambiguation, and Easier Ways phonetic simplification.
   - Hosting: External OpenAI-compatible API (`https://api.groq.com/openai/v1`).

### Custom-Trained / Research Models
1. **`rerank-v2` (MuRIL Cross-Encoder)**:
   - Architecture: Cross-encoder sequence classifier based on `google/muril-base-cased` (238M parameters).
   - Training: Trained on synthetic text substitution mishearings (12,035 synthetic rows generated by rule scripts).
   - Weights: Evaluated in PyTorch and exported to ONNX (fp32: 906 MB, int8: 228 MB). Model weights are kept out of Git.
   - Status: Research experiment. Controlled by `RERANKER_ENABLED` flag (defaults to off).
2. **LoRA Fine-Tuned Whisper-Small**:
   - Architecture: `openai/whisper-small` (244M parameters) with low-rank adaptation on attention projections ($r=16, \alpha=32$).
   - Pipeline: Documented in `training/train.py` and `training/README.md`.
   - Status: Research experiment. Never deployed in the production application or Docker container.

## 5. Data Quality, Privacy & Ethical Compliance

1. **Synthetic Data Boundaries**:
   - All synthetic datasets (`ml/data/train_all.csv`) are strictly labeled as rule-generated synthetic mishearings.
   - Synthetic data is never represented as genuine patient speech and is never used to make clinical efficacy claims.
2. **User Privacy Contract**:
   - User enrollment audio is stored strictly under `data/users/<user_id>/` and is deleted immediately upon account deletion via `DELETE /api/me`.
   - Attempt audio from Trainings exercises is processed in-memory or temporary files, deleted immediately after transcription, and never persisted to disk.
   - For child users (`kids-speaking`), attempt transcripts are stripped completely (`stored_transcript = None`).
   - User recordings are never exported or used to train shared models.
3. **No Tracked Large Data Artifacts**:
   - Git tracking audit confirmed zero audio files, zero model weights, and zero private recordings tracked in version control.

## 6. Model Architecture & Algorithm Audit

### Production Phrase Matching Pipeline (`src/matcher.py`)
1. **Text Normalization**:
   - Devanagari text is transliterated into ITRANS notation using `indic_transliteration.sanscript`.
   - Strips diacritics, dandas, and punctuation while preserving word boundaries.
   - Lowercases and normalizes whitespace.
2. **Similarity Scoring**:
   - Uses `rapidfuzz.distance.Levenshtein.normalized_similarity` on normalized ITRANS strings.
   - Produces a scale from 0 to 100.
3. **Usage & Contextual Priors**:
   - Context Boost (+6 points): Applied when the phrase context matches the user's active context (home, hospital, market).
   - Frequency Boost (+4 points): Scaled by phrase historical frequency (0 to 1).
   - Time Boost (+3 points): Scaled by phrase time-of-day bucket frequency (morning, afternoon, evening, night).
   - Hard Constraint: Total priors are capped at +13 points, mathematically preventing priors from overturning a clearly superior phonetic match.
4. **Algorithmic Complexity**:
   - Time Complexity: $O(N \cdot L_1 \cdot L_2)$ where $N$ is candidate count (~51 phrases) and $L$ is word length (~15 characters).
   - Execution Time: ~4 ms on CPU with zero allocation overhead.

## 7. Training Pipeline Audit

### `ml/train_rerank.py` (MuRIL Cross-Encoder)
- **Model**: `google/muril-base-cased` (238M parameters) with single-logit classification head.
- **Batching & Optimization**:
  - Batch size: 32 groups of 8 (intended + 4 hard negatives + 2 category negatives + 1 length negative).
  - Optimizer: AdamW ($lr=2 \times 10^{-5}$, warmup=5%).
  - Early stopping: Patience of 2 epochs based on validation top-1 accuracy.
- **Reproducibility**: Fixed random seed (`SEED = 7`).
- **Hardware Profile**: Evaluated on NVIDIA RTX 5070 laptop GPU (8 GB VRAM); training time ~12 minutes for 5 epochs.

### `training/train.py` (Whisper-Small LoRA)
- **Model**: `openai/whisper-small` (244M parameters) with LoRA on attention query and value projections ($r=16, \alpha=32$).
- **Optimization**:
  - Precision: `bfloat16` with gradient checkpointing.
  - Effective batch size: 32 (batch 8 with 4 accumulation steps).
  - Learning rate: $1 \times 10^{-4}$ with linear warmup.
  - Memory cap: `MEMORY_FRACTION = 0.9` prevents Windows WDDM driver system RAM spill.
- **Status**: Smoke-tested on synthetic audio tones only; zero training on patient speech.

## 8. Model Checkpoints & Artifacts

- **Repository Status**: Clean. Zero checkpoints, ONNX binaries, or PyTorch `.pt` files are stored in Git.
- **ONNX Export Findings (`ml/results/export.md`)**:
  - Exporting `rerank-v2` to ONNX yields:
    - PyTorch fp32: 906 MB (476 ms median latency).
    - ONNX fp32: 906 MB (412 ms median latency).
    - ONNX int8: 228 MB (250 ms median latency).
  - Int8 quantization causes a 7.9 percentage point drop on word accuracy (from 78.3% to 70.4%).
  - Given that rapidfuzz runs in 4 ms with 96.5% sentence accuracy, the 250 ms ONNX model offers no net benefit for production deployment.

## 9. Inference Pipeline & Backend Integration

1. **Integration Path**:
   - `web/src/Speak.jsx` -> `POST /api/me/recognize` -> `save_and_transcribe` (Gnani Prisma STT) -> `matcher.rank` -> `llm_judge.judge` (when ambiguous) -> HTTP response -> UI candidate cards.
2. **Fallback Robustness**:
   - If Gnani Prisma fails: returns HTTP 502 with structured retry notice.
   - If Reranker is absent or disabled: gracefully bypassed without logging errors or delaying inference.
   - If Groq LLM fails or times out: retains matcher's phonetic ranking immediately without stalling.
   - If Gnani Timbre TTS fails: browser `window.speechSynthesis` speaks the phrase automatically.

## 10. Model Evaluation & Quantitative Metrics

### Empirical Results Summary
- **Real Patient Recordings**: **N = 0**. No clinical or patient speech has been collected or processed.
- **Synthetic Test Evaluation (`ml/results/compare.md`)**:
  - Test sentences (n=1,060): Rapidfuzz top-1 = **96.5%**; Rerank-v2 top-1 = **97.3%** (+0.8% difference, within random margin).
  - Test words (n=442): Rapidfuzz top-1 = **56.8%**; Rerank-v2 top-1 = **78.3%** (gain observed on isolated single words).
  - Composed phrases (n=24): Rapidfuzz top-1 = **91.7%**; Rerank-v2 top-1 = **95.8%**.
- **Conclusion**: On conversational sentences, the deterministic rapidfuzz matcher is practically indistinguishable from the 238M neural cross-encoder while being 60 times faster and consuming zero GPU memory.

## 12. Final Recommendation

### **Recommendation: Option A (No Custom Training Required)**

**Rationale**:
1. **Production Adequacy**: The existing production speech architecture (Gnani Prisma STT + personalized Levenshtein fingerprint matcher + Groq Cloud AI judge) is verified, fully functional, and achieves sub-2.1s end-to-end turnaround.
2. **Clinical Alignment**: Sunn's core value proposition is personalized error-fingerprinting. It adapts to any individual's dysarthria with 2 to 3 takes, rather than requiring an impractical multi-speaker atypical acoustic model.
3. **Resource Stewardship**: Custom model training would consume significant developer time, GPU resources, and data that does not currently exist, with zero demonstrable benefit for the upcoming hackathon demonstration.
4. **Demo Readiness**: All 224 unit tests, schema validators, production Vite builds, and 131 Playwright E2E tests are green.
